# Архитектура

Все правила ниже **проверяются автоматически** (ESLint, `eslint.config.js`) —
нарушение не пройдёт ни коммит, ни CI.

## Слои

```
app       → точка сборки: AppModule, фабрика приложения, CLI-скрипты (main, migrate, seed, openapi)
modules   → бизнес-модули (auth, users, contacts)
core      → инфраструктура (config, database, logger, http, health)
common    → общие декораторы и схемы, без зависимостей от инфраструктуры
```

### Правило 1. Импорт только вниз

| Откуда    | Можно импортировать          |
| --------- | ---------------------------- |
| `app`     | modules, core, common        |
| `modules` | другие modules, core, common |
| `core`    | другие сегменты core, common |
| `common`  | только common                |

`core` ничего не знает о бизнесе: если инфраструктуре нужно поведение модуля,
модуль передаёт его через DI (как глобальный `JwtAuthGuard` регистрируется в `AppModule`).

### Правило 2. Только публичный API

Другой модуль или сегмент `core` импортируется **только через его `index.ts`**:

```ts
import { UsersService } from '../users/index.js' // ✔
import { UsersRepository } from '../users/users.repository.js' // ✖ boundaries/dependencies
```

В `index.ts` экспортируется только то, что нужно снаружи (лишнее найдёт Knip).
Внутренности модуля — репозиторий, таблица — наружу не выходят.

### Правило 3. Слои внутри модуля

```
controller → service → repository → table
   HTTP      логика       SQL        схема БД
```

| Файл              | Отвечает за                               | Ограничения                           |
| ----------------- | ----------------------------------------- | ------------------------------------- |
| `*.controller.ts` | HTTP: маршруты, контракт (`@ApiContract`) | не видит репозиторий, таблицы и SQL   |
| `*.service.ts`    | бизнес-логика, бросает `HttpException`    | не импортирует `drizzle-orm`          |
| `*.repository.ts` | запросы к БД                              | единственное место для SQL            |
| `*.table.ts`      | Drizzle-таблица                           | источник миграций                     |
| `*.schemas.ts`    | zod-схемы запроса и ответа                | — источник типов, валидации и OpenAPI |
| `*.module.ts`     | связывание через DI                       |                                       |
| `index.ts`        | публичный API модуля                      |                                       |

Новый модуль со всеми соглашениями: `npm run generate:module -- <name>`.

### Правило 4. Конфигурация только через `APP_CONFIG`

`process.env` читается только в `core/config` и в точках входа `src/app/*.ts`.
Все переменные описаны в `env.schema.ts` и проверяются при старте — приложение с
невалидным окружением не запустится, а ошибка перечислит каждую проблемную переменную.

```ts
constructor(@Inject(APP_CONFIG) private readonly config: AppConfig) {}
```

## Безопасность по умолчанию

- **Все маршруты требуют токен.** Публичные помечаются явно: `@Public()`.
  Забытый декоратор даёт 401, а не дыру.
- **Ответы фильтруются схемой.** `@ApiContract({ response: userSchema })` вырезает всё,
  чего нет в схеме, — `passwordHash` не утечёт, даже если сервис вернёт всю запись.
- **Входные данные валидируются схемой:** `@Body({ schema })`. Неизвестные поля
  отбрасываются, ошибки возвращаются списком `details`.
- **Rate limiting** глобальный (100/мин) и строже на `auth` (5/мин). Ограничитель
  срабатывает **до** проверки токена, поэтому перебор токенов тоже ограничен.
  Health-пробы не ограничиваются.
- **Пароли** — `scrypt` с параметрами OWASP; для несуществующего email всё равно
  выполняется сравнение хеша, чтобы по времени ответа нельзя было узнать, зарегистрирован ли адрес.
- **Логи** не содержат `Authorization` и cookie; входящий `x-request-id` принимается
  только из безопасных символов (защита от инъекций в логи).
- **Ошибки 5xx** логируются целиком, а клиенту уходит только `Internal server error` и `requestId`.

## Контракт API (OpenAPI)

zod-схемы — единственный источник истины: из них берутся типы TypeScript,
валидация запроса, очистка ответа и документация.

```ts
@Post('login')
@ApiContract({
  summary: 'Exchange credentials for an access token',
  response: authResponseSchema,
  errors: [HttpStatus.BAD_REQUEST, HttpStatus.UNAUTHORIZED],
})
login(@Body({ schema: loginRequestSchema }) body: LoginRequest): Promise<AuthResponse>
```

`openapi.json` коммитится в репозиторий: изменения контракта видны в diff PR, а
фронтенд генерирует из него типы. `npm run openapi:check` в CI не даст забыть его обновить.
Схемы, которые должны стать отдельными компонентами OpenAPI, помечаются `.meta({ id: 'Name' })`.

## База данных

- Таблица живёт в своём модуле: `src/modules/<module>/<name>.table.ts`.
- Имена в TS — camelCase, в SQL — snake_case (настройка `casing` у Drizzle).
- После изменения таблицы: `npm run db:generate` → SQL-миграция в `drizzle/` →
  просмотрите её и закоммитьте. `npm run db:check` не пропустит схему без миграции.
- Миграции **не** применяются при старте приложения. В проде это отдельный шаг
  релиза: `node dist/app/migrate.js` (init-контейнер, job, сервис `migrate` в compose).
- Миграции должны быть обратно совместимыми: старая версия приложения продолжает
  работать, пока выкатывается новая (expand → migrate → contract).

## Ошибки

Сервисы бросают стандартные исключения Nest (`NotFoundException`,
`ConflictException`, …). `AllExceptionsFilter` приводит любую ошибку — включая
ошибки валидации, Fastify (битый JSON, слишком большое тело) и неожиданные
исключения — к единому формату `ErrorResponse` с `requestId`.

## Тесты

| Тип  | Где                      | Что проверяет                          | Инструменты                                    |
| ---- | ------------------------ | -------------------------------------- | ---------------------------------------------- |
| Unit | `src/**/*.test.ts`       | логика сервисов, guard, фильтр, конфиг | Vitest, моки репозиториев                      |
| E2E  | `test/e2e/*.e2e.test.ts` | HTTP-контракт, безопасность, БД        | Testcontainers (PostgreSQL 18), `app.inject()` |

- E2E-тесты собирают приложение той же фабрикой `createApp()`, что и прод, — тест
  проверяет ровно то, что уходит в релиз.
- Rate limit считается по IP, поэтому независимые e2e-тесты используют
  `uniqueClient()` (свой адрес клиента).
- Тесты запускаются через SWC: он сохраняет метаданные декораторов, без которых не
  работает DI в Nest.
- Пороги покрытия — «храповик»: повышаем по мере роста, никогда не снижаем.
